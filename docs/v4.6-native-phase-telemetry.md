# V4.6 native schema-v3 telemetry gate

## Goal

V4.3–V4.5 added validated phase aggregation and comparison attribution. Their real-data demonstrations used deterministic offline backfills of frozen reports. V4.6 verifies the complete current path with a real provider:

`DeepSeek API → Agent decisions → bounded tools → Docker pytest → task snapshots → schema-v3 report → Markdown`

## Frozen contract

The manifest contains three authored deterministic fixtures, each run once with DeepSeek Flash and thinking explicitly disabled:

| Case | Request cap | Token cap | Verification |
|---|---:|---:|---|
| Toy addition | 8 | 12,000 | Docker full pytest |
| Username normalization | 8 | 16,000 | Docker full pytest |
| Optional config override | 8 | 16,000 | Docker full pytest |

The suite-level authorization is 24 requests. `verify_after_patch` is enabled and every expected changed file is declared before the run.

Per-case telemetry was generated natively:

| Case | Snapshots | Observed path |
|---|---:|---|
| Toy addition | 3 | locating → inspecting → verified |
| Optional config override | 4 | locating → inspecting → ready → verified |
| Username normalization | 5 | locating → inspecting → ready → verified |

The username task remained in `ready_to_patch` for two snapshots, so its five requests are visible as phase behavior rather than only a larger total.

## Scope

These are small authored fixtures selected to verify telemetry plumbing, not a new generalization benchmark. The gate demonstrates that schema-v3 reporting works on the real provider path; it does not improve or re-estimate upstream repair reliability.
