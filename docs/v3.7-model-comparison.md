# V3.7 frozen Flash/Pro model comparison

## Question and protocol

V3.7 回答一个具体问题：在相同 RepoFix Harness、仓库、任务、Docker、请求与 token 上限下，`deepseek-v4-pro` 是否比默认 `deepseek-v4-flash` 更适合 Python repository repair？

两组模型都使用 OpenAI-compatible Chat Completions、原生 tool calling、JSON fallback、`thinking=disabled`、2,048 普通输出上限和 4,096 patch 输出上限。官方文档把 V4 Pro 描述为 Agent 能力增强模型，并给出 Flash/Pro 的同接口支持与峰谷价格：[DeepSeek V4 Pro release](https://api-docs.deepseek.com/updates/)、[Models and pricing](https://api-docs.deepseek.com/quick_start/pricing/)。

成本统一按峰值保守单价估算：

| Model | Cached input / 1M | Input / 1M | Output / 1M |
|---|---:|---:|---:|
| Flash | $0.014 | $0.44 | $1.32 |
| Pro | $0.044 | $1.32 | $3.96 |

所有运行发生在冻结的 RepoFix 3.6.0 源码上：Harness source SHA-256 `512442d05db2a086f6df08f84aab459eb16e3117338e8c1dcac502b9d2a461f0`。V3.7 的比较器代码在实验完成后加入，不参与模型轨迹。

## Click help-rendering comparison

Manifest SHA-256: `0d6f1dc402fd660abce75b1a1df6e93d3787fb197bac5a624728b11b10a542bb`。

| Metric | Flash | Pro | Pro delta |
|---|---:|---:|---:|
| Verified | 3/3 | 3/3 | 0 |
| Exact scope | 3/3 | 3/3 | 0 |
| Requests | 16 | 10 | -37.50% |
| Tokens | 46,554 | 25,323 | -45.61% |
| Peak estimated cost | $0.01643667 | $0.03117656 | +89.68% |

三个配对 trial 中，Pro 的 requests 和 tokens 都更少。但成功率已在两组同时饱和，结果只能证明 Pro 在这个简单类型守卫 Bug 上路径更短，不能证明修复成功率更高。

## h11 incremental chunk-footer comparison

Manifest SHA-256: `fa8281a7b42c924a54e0a26b4e74ca3ca18fdf5f1f461d7bcf693dc46a9a3e23`。

| Metric | Flash | Pro | Pro delta |
|---|---:|---:|---:|
| Verified | 1/3 | 1/3 | 0 |
| Exact scope | 3/3 | 3/3 | 0 |
| Requests | 32 | 34 | +6.25% |
| Tokens | 169,549 | 167,003 | -1.50% |
| Peak estimated cost | $0.06830198 | $0.19605247 | +187.04% |

逐 trial 结果不是同一次同时成功：一对 Flash-only success、一对 Pro-only success、一对 both failed。Pro 在 requests 与 tokens 上均为 1 对更优、2 对更差。各模型只有三个 stochastic trials，不能据此声称胜率相等；可以确认的是本轮没有观察到 Pro 的成功数量提升。

## Strict comparison artifact

V3.7 新增 `repofix-compare`。它先调用 evaluation report 聚合校验，再要求以下身份一致：

- suite 与 manifest SHA-256
- 每个 source snapshot SHA-256
- Harness version/source SHA-256 与 Python/module path
- output limits、thinking、JSON 和 native tool settings
- Docker runtime fingerprint
- suite request authorization 与 planned ceiling
- 每个 trial 的 task/case/variant/source/test/backend/timeout/context/expected scope

模型名和三档价格是允许变化的实验变量。比较器输出 `comparison.json` 与 `comparison.md`，包含整体 delta、相对变化、逐 trial 成功组合以及 requests/tokens better/tied/worse。

## Decision

RepoFix 默认模型保持 `deepseek-v4-flash`。Pro 在 Click 上更省 tokens，但没有增加成功数且成本更高；在 h11 上也没有增加成功数。这个结论只适用于当前 non-thinking、两类 Bug、每组三次的冻结评测，不等于 Pro 在更大样本或 thinking-high 下无价值。
