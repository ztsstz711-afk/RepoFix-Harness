# V3.8 Pro thinking-high comparison

## Question

V3.7 表明 Pro non-thinking 在 Click 与 h11 上没有增加成功总数。V3.8 单独检验：固定为 `deepseek-v4-pro` 时，官方默认 high effort 的 thinking mode 能否在复杂 h11 增量协议修复上减少错误修订并提高完成数？

DeepSeek 官方说明 `thinking.enabled` 的默认 effort 为 high，reasoning tokens 计入 completion usage：[Thinking Mode](https://api-docs.deepseek.com/guides/thinking_mode/)。RepoFix 使用 Chat Completions 的 `extra_body={"thinking":{"type":"enabled"}}`，没有为候选组扩大 request 或 token 上限。

## Aborted pre-gate

第一次探索运行使用 45 秒 Provider timeout。一个 trial 在第六次请求超时，随后账户余额不足导致另外两条返回 402；该组只有 47,822 已记账 tokens，0/3 不代表模型失败，不进入最终比较。

V3.8 随后把 `request_timeout_seconds` 写入 evaluation identity，并将最终两组共同冻结为 120 秒。比较器也扩展为显式维度：`model` 对照锁定 thinking，`thinking_mode` 对照锁定模型和价格。不同 timeout 的报告会被拒绝比较。

## Frozen identity

- model: `deepseek-v4-pro`
- request timeout: 120 seconds
- thinking variable: `disabled` vs `enabled`（official default high）
- per-trial limits: 12 requests / 60,000 tokens
- max output: 2,048 navigation / 4,096 patch
- manifest SHA-256: `fa8281a7b42c924a54e0a26b4e74ca3ca18fdf5f1f461d7bcf693dc46a9a3e23`

- pre-release harness version: `3.7.0`

## Results

| Metric | Non-thinking | Thinking-high | Delta |
|---|---:|---:|---:|
| Verified | 2/3 | 3/3 | +1 |
| Exact scope | 3/3 | 3/3 | 0 |
| Requests | 33 | 22 | -33.33% |
| Tokens | 162,442 | 137,393 | -15.42% |
| Peak estimated cost | $0.18748136 | $0.21714925 | +15.82% |

三个配对 trial 中两个 both-success，一个 thinking-only success。Thinking-high 在三对 requests 和 tokens 上都更少；每项双侧 exact sign test 的 p 值仍为 0.25，样本不足以说明稳定优势。

从轨迹看，thinking-high 通常用更少的修订轮次到达可验证补丁；它虽然降低总 tokens，但 reasoning output 的单位成本占比更高，因此保守成本仍上升 $0.02966789。最终两组峰值估算合计 $0.40463061；实际运行处于低价时段，但报告保持峰值单价，便于预算上界审计。

## Decision

RepoFix 默认仍保持 Flash/non-thinking，不加入自动难度路由。V3.8 只支持以下更窄结论：对于这个复杂 h11 状态机案例，Pro thinking-high 在固定预算的小样本中提高了完成数并缩短轨迹，值得在新的真实难例上独立复验。
