# V4.4 grouped repair-phase telemetry

## Goal

V4.3 made overall repair-phase behavior auditable, but a suite-level total can hide which case or experiment variant caused extra navigation or patch recovery. V4.4 adds two derived views without changing prompts, policies, or provider requests:

- `phase_telemetry_by_variant` for controlled experiment arms;
- `phase_telemetry_by_case` for individual bug families.

Each group contains the same complete contract as the overall summary: snapshot count, phase counts, changed-phase transitions, and target-read grace activations.

## Integrity and compatibility

New reports use schema v3. Before publication, the validator independently rebuilds overall, variant, and case telemetry from `tasks[*].context_snapshots`. Missing group identities, inconsistent grace flags, changed counts, or altered transitions reject the report.

Schema-v1 and schema-v2 reports remain valid and resumable. Resuming an incomplete historical report writes the next progress snapshot using the current schema rather than mixing task results.

## Frozen V4.2 backfill

No model was called. The checksum-qualified V4.2 nine-trial report was grouped offline:

| Case | Snapshots | Patch-attempt-failed snapshots | Target-read activations |
|---|---:|---:|---:|
| Click strict help equality | 14 | 2 | 0 |
| `last()` with disabled reverse | 15 | 4 | 0 |
| Empty reversed numeric range | 14 | 0 | 0 |

The aggregate still totals 43 snapshots and zero target-read activations. The grouped view adds a useful diagnosis: the `last()` family consumed its extra decision snapshot in patch rejection/recovery, while the numeric-range family reached verification without a rejected patch phase.

## Scope

This is evaluation observability, not a model-quality claim. The next useful step is computing phase deltas inside strict baseline/candidate report comparisons so experiment differences can be attributed without manually joining two grouped summaries.
