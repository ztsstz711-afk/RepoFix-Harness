总成本估算为 $0.09082377。输入 219,186 tokens，输出 12,598 tokens；format/transient retries 均为 0。失败各一次：running 在一次未完成修订的补丁后触发 token reserve，Tomli 在第二次补丁后用尽 12-request budget。失败任务也只触及预期实现文件，但没有通过完整验证，因此不计 success。

## Revision-cap follow-up

主门禁暴露出一个 Harness 状态机问题：focused test 或 patch 工具失败后，`patch_needs_revision` / `patch_attempt_failed` 长期允许继续 read/search。V2.2 将最近一次 patch 后的成功导航限制为两次，随后转为 `patch_due`，只暴露 `apply_patch`。

`evals/revision-cap-v2.2.json` 是独立 follow-up，不用于改写 4/6 主结果：

- Verified: 2/2
- Exact scope: 2/2
- Requests: 16
- Tokens: 66,010
- Format retries: 0
- Estimated cost: $0.02588891

## Interpretation

与 V2.0 默认 thinking 下相同两个困难案例的 1/6 合计结果相比，冻结 non-thinking gate 的 4/6 是明显改善，同时输出与格式失败大幅下降。但样本仍小，且 revision-cap follow-up 只有每案例一次。可信结论是：显式关闭 thinking 已成为当前低成本 DeepSeek 工具闭环的合理默认；revision cap 值得保留并应在下一次重复门禁中继续验证。
