# V1.3 repeated context A/B result

Run date: 2026-08-27  
Model: `deepseek-v4-flash`  
Suite: `evals/context-ab.json`  
Execution backend: restricted Docker

The suite compares the same optional-config repair with traceback/import context enabled and disabled. Each variant runs three times from a fresh isolated repository copy. Trials are interleaved (`on-1`, `off-1`, `on-2`, `off-2`, ...) to reduce ordering effects.

| Metric | Context on | Context off |
|---|---:|---:|
| Trials | 3 | 3 |
| Successful repairs | 3/3 | 3/3 |
| Expected scope matches | 3/3 | 3/3 |
| Requests, total | 9 | 18 |
| Requests, mean / median / range | 3 / 3 / 3–3 | 6 / 6 / 6–6 |
| Tokens, total | 13,718 | 27,671 |
| Tokens, mean | 4,572.67 | 9,223.67 |
| Tokens, median / range | 4,547 / 4,305–4,866 | 9,217 / 9,155–9,299 |
| Estimated cost, total | $0.00676813 | $0.00953296 |
| Estimated cost, mean | $0.00225604 | $0.00317765 |

Across these six trials, context seeding preserved success and exact change scope while reducing mean requests by 50%, mean tokens by about 50.4%, and estimated mean cost by about 29.0%. The context-on first request was larger because it included source evidence, but it avoided three subsequent navigation calls.

This remains a small controlled comparison on one fixture and one model, not a general statistical claim. V1.3 adds the evaluation machinery needed to repeat this design across more tasks and providers.
