# V1.8 phase-aware tool policy

## Goal

V1.7 的 `patch_due` 仍只是 prompt 提示。V1.8 把 repair phase 转换为 Provider 实际可见的工具集合，并在解析后再次检查动作是否属于当前阶段：

- `patch_due`：仅 `apply_patch`；
- `verified_patch`：`git_diff`、`git_status`、`finish`；
- `patch_needs_verification`：`run_command`、`git_diff`、`git_status`；
- patch failure/revision：保留读取、局部修改和定向测试所需的最小集合；
- locating/inspecting/ready：保留完整注册工具。

同一策略同时生成原生 Function Calling 的 `tools`、JSON fallback 文本合同，并在 `parse_message_action` / `parse_action_json` 后检查。兼容端点即使返回未声明工具，也不能绕过阶段策略。

## Offline verification

发布前全量回归为 196 passed。定向测试额外覆盖：

- `patch_due` 请求只包含一个 `apply_patch` function schema；
- 阶段外原生 tool call 被拒绝；
- Agent Loop 把 Context 计算出的 phase 传给可感知策略的 Provider；
- 离线 Tomli 风格闭环依次传递 locating、inspecting、ready_to_patch、verified_patch。

## Fixed three-case gate

`evals/phase-policy-v1.8.json` 冻结三个 V1.5 checksum-qualified 上游案例。每个案例只运行一次，所以这是跨案例 feasibility/compatibility gate，不是统计稳定性结论。

- Docker 禁网执行；
- baseline 和 patch feedback 使用定向 regression；
- 最终成功必须通过完整上游套件；
- 每案例最多 12 requests，总授权 36；
- token admission 分别为 32,000、40,000、68,000；
- 所有案例启用 Harness-owned post-patch focused verification；
- expected changed files 只用于评测，不进入模型 prompt。

|---|---:|---:|---:|---:|---:|---|---|---:|
| Negative `sliced()` size | success | 6 | 7 | 25,739 | 1 | `more_itertools/more.py` | 730 passed, 19,938 subtests | $0.01118286 |
| Running min/max stability | token reserve | 5 | 8 | 35,386 | 4 | none | 2 failed, 730 passed, 19,938 subtests | $0.02289373 |
| Tomli dotted key limit | success | 7 | 11 | 61,084 | 4 | `src/tomli/_parser.py` | 17 passed, 744 subtests | $0.03279786 |

Aggregate: **2/3 verified repairs**, **2/3 exact change-scope matches**, 26/36 authorized requests, 122,209 tokens, estimated cost $0.06687445. 每个任务均在自己的 token admission ceiling 内停止或完成。

## Tomli repair evidence

Tomli 在前六步完成 list/search/read 导航。第 7 个 context 的 phase 为 `patch_due`，因此 Provider 只暴露 `apply_patch`。模型随后在 `parse_key` 循环中提交一个局部替换：每增加 dotted key part 后比较 `len(key)` 与现有 `MAX_INLINE_NESTING`，超限时抛出满足 regression message 的 `RecursionError`。

Harness 自动定向验证得到 1 passed。剩余 6,916 tokens 无法容纳估算为 8,211 tokens 的下一请求，因此 admission 停止；已有 changed patch 随后触发独立完整验收，得到 17 passed、744 subtests passed。最终 changed-file scope 精确命中 parser 文件。该成功不依赖模型主动发送 `finish`，而依赖 Harness 在预算边界对已有补丁执行客观验收。

## Comparison and limitation

V1.5 指定 gate 也是 2/3，但成功的是两个 more-itertools 案例；V1.8 成功的是 sliced 与此前持续失败的 Tomli。不能据此宣称整体成功率提升，因为每个版本都只有一个 trial，模型轨迹存在随机性。可以确认的是：

1. 阶段工具策略没有破坏 sliced 的完整闭环；
2. `patch_due → apply_patch only` 在本次冻结 Tomli gate 中直接产生了合法局部修改；
3. Provider 级 token admission 对三个任务都生效；
4. running stability 仍受空响应/格式重试影响，是下一轮稳定性工作的主要反例。
