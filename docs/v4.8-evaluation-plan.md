# V4.8 breadth evaluation plan

## Question

Can the frozen V4.7.1 Harness repeatedly repair the full set of prepared upstream Python regressions under one consistent Docker, budget, verification, and reporting contract?

This gate measures breadth and stability over known regression families. It is not a held-out generalization benchmark and must not be described as SWE-bench performance.

## Frozen contract

- Harness baseline: `v4.7.1` / `8ccc88721a4a802b97b1996307dc2e2c06d37a1a`.
- Manifest: `evals/breadth-regression-v4.8.json`.
- 9 distinct bugs, 5 upstream projects, 3 repetitions each, 27 total trials.
- Restricted Docker pytest for baseline, focused feedback, and final acceptance.
- Automatic verification after every effective patch.
- Exact expected changed-file scope for every task.
- DeepSeek Flash with thinking disabled; Provider identity and prices are recorded in the report.
- Maximum authorization: 324 model requests. Each task retains its own step, request, token, and command-timeout ceiling.
- No cherry-picking, replacement trials, prompt edits, or Harness edits after the gate begins. Resume may only continue the same fingerprint-validated report.

## Measures fixed before execution

Primary measures:

- independently verified repair rate over all 27 trials;
- exact changed-file scope rate over all successful repairs;
- per-case success count over three repetitions.

Secondary measures:

- requests, input/output/total tokens, estimated cost, and retries;
- repair-phase transitions and target-read activation;
- failure reason distribution, including budget, Provider, patch, and final-test failures.

The release gate is considered useful evidence when at least 19/27 trials are independently verified, every successful repair has exact file scope, and the report passes its internal aggregate and identity validator. A lower result is still published as a valid negative finding.

## Follow-up held-out gate

After this regression gate is frozen and run, prepare 3-5 new upstream bugs that were never used to tune prompts, phase policy, budgets, or context selection. Keep those source fixes hidden from the Agent and publish them separately as held-out evidence.
