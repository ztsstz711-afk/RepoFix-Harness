# V1.7 patch readiness

## Goal

V1.6 已能把 Tomli 的失败测试经过本地 facade 定位到 `src/tomli/_parser.py`，但模型会继续读取已知区域，且原生工具调用的非法或空响应会消耗有限请求。V1.7 只优化“证据到补丁”的转化，不增加请求、token、步骤或文件权限。

## Changes before the fixed gate

- `ArgumentSpec` 明确保存 prompt shape、JSON type、description 和数值下界，替代从示例字符串猜参数类型。
- `apply_patch` Function Calling schema 用 `oneOf` 表达两种互斥模式：`old_text` + `new_text` 的局部替换，或仅 `content` 的整文件写入。
- Provider 成功重试后仍把之前的格式错误写入 trace，而不是只累计一个 retry 数字。
- Context 根据 history 生成 `locating`、`inspecting`、`ready_to_patch`、`patch_needs_verification`、`patch_needs_revision` 和 `verified_patch` 阶段，并给出下一动作优先级。
- 离线 Tomli 风格集成测试验证 traceback/facade source seed、搜索、窄范围读取、局部替换、Harness 自动定向测试和最终验收可以完整闭环。

发布前全量回归：191 passed。新的 Function Calling schema 另用一次只读真实 smoke request 验证，`deepseek-v4-flash` 在 1 次请求、1,556 tokens 内返回合法 `list`。

## Fixed gate

`evals/patch-readiness-v1.7.json` 保持原合同：同一个 checksum-qualified Tomli workspace，最多 12 requests、68,000 tokens，Docker 禁网，定向 regression feedback，完整上游 suite 最终验收，预期只修改 `src/tomli/_parser.py`。

| Status | Steps entered | API requests | Tokens | Format retries | Changed files | Cost |
|---|---:|---:|---:|---:|---|---:|
| token budget reserve | 8 | 10/12 | 60,967/68,000 | 3 | none | $0.02972466 |

动作轨迹为：`list → read test → search key_value_rule → read parser → search allowed → read parser → read constants`。从第 4 个 model context 开始，阶段持续为 `ready_to_patch`，但模型仍进行了四次导航。第 8 步的原生响应没有产生可解析动作；下一次重试估算需要 9,868 tokens，而只剩 7,033，因此 Provider 级 admission 正确停止，没有再次越过 manifest token ceiling。baseline 和最终结果均保持 1 failed、16 passed、744 subtests passed。

## Changes motivated by the gate

本次 gate 后只进行确定性的 Harness 修正，不再调用 API 选择性重跑：

- 原生 Function Calling 不再在 system prompt 中重复完整文本 action contract；3,309-character tool schema 已提供参数定义。只有原生调用失败、切换 JSON fallback 时才注入 1,070-character 文本合同。
- 五次成功 read/search 仍未修改时，repair phase 升级为 `patch_due`，明确禁止继续 list/search/read，并要求使用已观察到的 exact text 做最小局部替换。
- 格式错误现在带 `native_tools`、`json` 或 `text` 标签；无 tool calls 且 content 为空时报告 `model returned neither tool calls nor content`，不再只显示 JSON parser 的 column 1 错误。

## Conclusion

V1.7 证明 token 预算边界已经按设计生效，也证明“提示 evidence 已足够”本身不足以让当前模型稳定提交 patch。新增的 `patch_due` 和去重 prompt 为下一次冻结 gate 提供了更强、更节省上下文的 Harness 行为，但本版本不把 gate 后代码与 gate 前失败结果混合，也不声称 Tomli 已修复。
