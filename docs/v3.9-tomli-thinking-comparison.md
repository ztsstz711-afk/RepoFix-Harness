# V3.9 Tomli thinking-high comparison

## Question

V3.8 在 h11 增量协议状态机上观察到 Pro thinking-high 的正向小样本结果。V3.9 检查这项收益能否跨项目复现：固定 `deepseek-v4-pro`，在 checksum-qualified Tomli dotted-key parser 真实上游回归上比较 non-thinking 与官方默认 high-effort thinking。

该案例来自 `hukkin/tomli` 的公开父 commit `c20c49113890c226ffb27a67befe20d14fcf0c73` 和修复 commit `e1fdb94bc998377f1c2545c7cd4f70ff2a3fb4e4`。buggy workspace 保留父版本 `src/tomli/_parser.py`，只导入修复 commit 的回归测试；Agent 看不到 reference fix。

## Qualification and frozen identity

- buggy focused test: 1 failed
- fixed-reference focused test: 1 passed
- model: `deepseek-v4-pro`
- request timeout: 120 seconds
- thinking variable: `disabled` vs `enabled`（official default high）
- per-trial limits: 12 requests / 80,000 tokens

版本号在冻结运行后提升为 3.9.0。两组使用相同 manifest、source、Harness、Docker、timeout、预算、价格和任务顺序；`repofix-compare --dimension thinking_mode` 在生成比较前重验了这些身份。

## Results

| Verified | 3/3 | 3/3 | 0 |

三对 trial 均为 both-success，没有 format 或 transient retry。Thinking-high 的逐对 token 增量为 +7,149、+6,669、+10,993；三对全部由 non-thinking 使用更少 tokens，双侧 exact sign test p=0.25，样本仍不足以外推稳定胜率。两组峰值估算合计 $0.20536939。

## Interpretation and decision

Tomli 任务的失败位置、目标函数和局部修改路径较直接。Non-thinking 已在 6–7 次请求内稳定完成，额外 reasoning 没有减少导航或修订轮次，因此主要转化为更多 output 与后续输入上下文。这个结果与 h11 相反：h11 的 thinking-high 减少了错误修订并增加一个成功，Tomli 则没有成功率空间且成本明显上升。

因此 RepoFix 继续默认 Flash/non-thinking，也不加入“困难任务自动开启 Pro thinking”的规则。V3.8 与 V3.9 共同支持的更窄结论是：thinking 的价值依任务结构而变；在形成跨更多未见上游项目的证据前，只应作为显式、可审计的实验变量。
