# V0.6 Loop stability

V0.6 reduces wasted model calls without turning the Agent into a rule-based repair pipeline.

## Output compaction

`repofix/text.py` keeps the beginning and end of oversized text and inserts an explicit omitted-character marker. `ToolRuntime` applies this to every observation, and `ContextBuilder` applies a smaller per-observation limit before enforcing the final prompt limit. This preserves traceback headers and pytest summaries together.

## Progress summary

The context header carries a compact list of files actually changed by the Agent and the latest Agent-requested pytest outcome. These facts survive even when older trace events no longer fit.

## Repeated-action guard

`RepeatedActionGuard` fingerprints the tool name and arguments, ignoring rationale wording. By default, two identical actions may execute; a third identical action before any real file change stops the run as `stalled` with `failure_kind=repeated_action`.

A successful `apply_patch` resets the repetition window. `finish` is never blocked, and different reads or searches are not treated as repeats. The model still chooses every repair action; the Harness only prevents a demonstrably repeated loop.
