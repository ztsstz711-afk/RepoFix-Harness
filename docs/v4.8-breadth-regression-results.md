# V4.8 breadth regression results

## Result

RepoFix evaluated the frozen V4.7.1 Harness on nine prepared upstream Python bugs from five projects. Each case ran three times in a fresh Docker-isolated workspace, for 27 trials in total. DeepSeek produced **22 independently verified repairs out of 27 (81.5%)**. Every successful repair changed exactly the expected file (**22/22, 100%**).

This passed the release criterion frozen before execution: at least 19 verified repairs, exact scope for every successful repair, and a report accepted by the internal aggregate validator.

| Metric | Result |
|---|---:|
| Verified repairs | 22/27 (81.5%) |
| Exact scope among successful repairs | 22/22 (100%) |
| Scope match across all trials | 25/27 (92.6%) |
| Model requests | 191/324 authorized |
| Total tokens | 718,910 |
| Retries | 3 format, 0 transient |
| Estimated API cost | $0.26840522 |
| Wall-clock evaluation time | about 14 minutes |

The all-trial scope count includes failures. Two failed h11 trials stopped without producing a patch, so they count as scope mismatches; the other three failed trials still changed only the expected file.

Seven of nine cases were stable at 3/3. The two remaining cases account for all five failures and expose a clear long-trajectory weakness rather than an infrastructure or network problem.

## Failure analysis

- Four trials stopped at the token-reserve admission check. The Harness refused to begin a model request that could exceed the task's frozen token budget.
- One trial reached the 12-request ceiling. Its partial patch remained in the expected file but did not pass final acceptance.
- The h11 chunk-footer case failed 3/3 and consumed about 55k tokens per trial. It repeatedly entered patch-revision loops and is the clearest target for the next Harness improvement.
- The ItsDangerous case succeeded 1/3. One successful repair was objectively accepted at the request boundary; the two failures were retained without rerunning or increasing their budgets.
- No transient API retry occurred. All nine focused baselines failed before repair, so no success was vacuous.

## Reproducibility and limits

The manifest was committed before execution. It fixes the source snapshots, task order, three repetitions, Docker backend, focused and full acceptance commands, model settings, request/token ceilings, and exact changed-file oracle. The final schema-v3 report passed `validate_evaluation_report` and records the manifest, source, Harness, and Docker fingerprints.

This is a **known-regression breadth test**, not a held-out generalization result and not SWE-bench. These bugs had been used during earlier development, although this 27-trial aggregate was not cherry-picked or selectively rerun. The next evidence gate should therefore use 3-5 upstream bugs never used while designing RepoFix.
