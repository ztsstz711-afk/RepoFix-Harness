# V1.6 navigation memory and native tools

## Goal

V1.6 不增加 Agent 数量或放宽执行权限，只解决 V1.5 Tomli 门禁暴露的四个 Harness 问题：有限 context 中会丢失旧导航证据、失败堆栈经过本地 facade 时到不了实现、补丁后验证依赖模型主动触发，以及兼容模型输出 JSON 动作时会浪费格式重试。

## Harness changes

- `read` 和 `search` observation 保存结构化路径、行范围、总行数、查询、命中数和截断状态。
- 每轮 context 携带有界的 `navigation_summary`；选择历史时跳过过大的中间 observation，使较小但关键的旧 search/patch 证据仍可保留。
- 失败 context 用 AST 追踪 traceback 函数实际调用的本地模块属性，最多跨三层 facade/re-export，不导入或执行目标仓库代码。
- 可选的 `verify_after_patch` 在修改产生 diff 后由 Harness 自动执行定向 `test_command`；最终成功仍必须独立通过 `final_test_command`。
- 中央 action registry 同时生成 prompt 说明与 OpenAI-compatible Function Calling schema。Provider 默认优先解析并校验原生 tool call，无合法调用时下一次尝试回退 JSON mode。
- DeepSeek V4 thinking 模式不接收 `tool_choice` 参数，因此请求只携带 `tools`，使用服务端默认的自动选择。若兼容端点返回并行调用，Harness 按响应顺序执行第一个通过中央 validator 的动作，其余动作留给下一轮依据新 observation 重新判断。
- 请求预算在格式重试期间耗尽时，最终 trace 保留最后一条格式错误，避免只看到笼统的 `request_budget`。
- Agent Loop 把本轮剩余 token allowance 下沉给 Provider；格式重试前使用上一响应的输入量加最大输出量估算下一请求，若无法安全容纳则以 `token_budget_reserve` 停止。

## Fixed evaluation contract

`evals/navigation-memory-v1.6.json` 只包含 V1.5 未完成的 Tomli dotted-key case：

- 同一个 checksum-qualified buggy workspace；
- 定向 regression baseline 与 patch feedback；
- Docker 禁网隔离；
- 完整上游测试作为最终 acceptance；
- 最多 12 次模型请求、68,000 预估 token admission ceiling；
- 预期修改范围仅为 `src/tomli/_parser.py`，该信息不进入模型 prompt。

## Calibration evidence

在原生工具调用冻结前，三个单次诊断 gate 分别验证了不同改进，但都没有被计为成功：

| Gate | Result | Requests/tokens | Evidence |
|---|---:|---:|---|
| Navigation memory | 0/1 | 12 / 62,881 | 第 7 步首次修改准确命中 parser 文件，但后续重试耗尽预算 |
| Post-patch verification | 0/1 | 12 / 64,791 | 未产生补丁 |
| Three-hop facade seed | 0/1 | 12 / 76,649 | 首轮 context 准确包含 test、facade 与 parser，实现定位改善但未转化为补丁 |

这些是开发诊断，不拼接成成功率，也不从中挑选最佳 trial。

## Native-tool gate

先用一个只读真实请求验证协议：`deepseek-v4-flash` 在 1 次请求、1,279 tokens 内返回合法 `list` tool call。该 smoke test 不修改仓库。

随后对冻结的 Tomli manifest 运行一次完整 gate：

| Status | Steps | API requests | Tokens | Format retries | Changed files | Cost |
|---|---:|---:|---:|---:|---|---:|
| request budget exhausted | 7 | 12/12 | 92,445 | 6 | none | $0.04700295 |

运行成功通过 preflight，定向 baseline 稳定失败；failure seeding 首轮提供了 `tests/test_misc.py`、`tests/__init__.py` 和 `src/tomli/_parser.py` 三个来源。Agent 随后完成 list、parser read、symbol search 和多次窄范围 read，但在准备下一动作时，Provider 内部格式重试耗尽剩余请求。没有 patch，因此完整测试仍为 1 failed、16 passed、744 subtests passed。

这次运行同时发现：原来的 run-level token admission 只发生在 Agent action 之间，单个 `next_action` 内部的格式重试可让实际用量越过 manifest 的 68,000 ceiling，因而出现 92,445 tokens。该数值如实保留，不能被解释为遵守了 token 上限。V1.6 发布代码随后加入 Provider 级 retry admission 单测；在剩余额度容纳不了下一次估算请求时会先停止。为避免用修复后的重复 trial 挑选结果，本版本不再调用 API 重跑该 gate。

## Conclusion

V1.6 的协议、状态、验证和 Provider 内部预算设施均已通过离线单测与真实 API smoke test，但固定 Tomli case 仍未闭环。当前瓶颈已经从“找不到实现文件”缩小为“模型在有限请求内没有稳定地从证据转向合法 patch”。下一版本应先利用新增的 retry diagnostics 分析具体非法 patch schema，再考虑 action schema 拆分或更强模型；不应仅提高请求上限反复运行。
