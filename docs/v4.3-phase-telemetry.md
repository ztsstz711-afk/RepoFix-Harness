# V4.3 repair-phase telemetry

## Problem

V4.1 introduced the bounded `target_read_due` policy and V4.2 verified that it stayed inactive across 43 snapshots from nine stable upstream repair trials. That conclusion was reproducible from the saved task data, but obtaining it still required manually traversing every task's `context_snapshots`.

V4.3 makes policy behavior a first-class evaluation result without changing the Agent prompt, tool policy, or model path.

## Report contract

Evaluation report schema v2 adds `phase_telemetry`, derived only from task snapshots:

- `snapshot_count`: every context snapshot created before a model decision;
- `phase_counts`: snapshots grouped by `repair_phase`;
- `transition_counts`: consecutive phase changes within each task, excluding same-phase stays and cross-task boundaries;
- `target_read_grace_activations`: entries into `target_read_due` within each task.

The report validator recomputes the complete object from task details. A changed count, transition, activation, or inconsistent `target_read_grace` flag prevents report publication. Schema-v1 reports remain valid and resumable; newly built progress and final reports use schema v2.

## Frozen V4.2 backfill

The existing V4.2 cross-project regression report was read without running a provider again. Offline aggregation produced:

| Metric | Value |
|---|---:|
| Tasks | 9 |
| Context snapshots | 43 |
| Target-read grace activations | 0 |
| `locating` snapshots | 9 |
| `inspecting` snapshots | 8 |
| `ready_to_patch` snapshots | 5 |
| `patch_attempt_failed` snapshots | 6 |
| `patch_needs_verification` snapshots | 6 |
| `verified_patch` snapshots | 9 |

The zero-activation conclusion matches V4.2's manual audit. The new mechanism therefore preserves the frozen result while making future policy gates directly inspectable in `report.json` and `report.md`.

## Scope

V4.3 is an observability and report-integrity release. It does not claim a repair-quality improvement and does not spend additional model requests. The next useful extension is case/variant-level phase aggregation for controlled comparisons.
