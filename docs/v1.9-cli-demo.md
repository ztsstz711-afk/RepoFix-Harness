# V1.9 CLI demonstration

## Purpose

V1.9 不增加 Web UI。它把现有 trace 中最重要的信息整理成终端实时视图，使一次真实修复可以直接用于开发检查、README 演示和面试讲解，同时保留 `.repofix/result.json` / `trace.json` 作为权威机器数据。

实时事件显示：

- preflight 与 warning 数；
- baseline pytest before 状态；
- 每轮 repair phase、context 大小、seeded source 数和剩余 request/token；
- action、目标路径及执行成功状态；
- patch 后 Harness-owned focused pytest；
- Provider 内部格式重试次数；
- budget-boundary repair 是否被独立验证。

最终摘要显示 status、baseline → final、changed files、steps、requests/tokens/retries、估算成本、backend、模型 summary、失败/rollback（如有）和 result JSON 路径。

## Output modes

```powershell
# 实时步骤 + 最终人类可读摘要
repofix --repo <repo> --task <task>

# 仅最终人类可读摘要
repofix --repo <repo> --task <task> --quiet

# 仅最终机器可读 JSON，不混入进度行
repofix --repo <repo> --task <task> --json
```

## Real DeepSeek toy run

演示把 `examples/toy_repo` 复制到临时目录，使用 Docker backend、`verify_after_patch`、最多 6 requests 和 12,000 tokens。源 fixture 未被修改。

```text
[preflight] PASS  warnings=2
[baseline] FAIL  backend=docker
[step 01] MODEL  phase=locating context=1520 chars seeded_sources=2 remaining_requests=6 remaining_tokens=12000
[step 01] APPLY_PATCH  PASS  calculator.py
           focused pytest PASS
[step 02] MODEL  phase=verified_patch context=2718 chars seeded_sources=0 remaining_requests=5 remaining_tokens=10312
[step 02] FINISH

=== RepoFix Result ===
Status: SUCCESS
Tests: baseline FAIL -> final PASS
Changed files: calculator.py
Steps: 2
Model usage: 2 requests, 3323 tokens, 0 retries
Estimated cost: $0.001828
Backend: docker
```

模型提交的是单行 localized patch：`return a - b` → `return a + b`。Focused 和 final pytest 均为 1 passed。由于临时目标不是 Git worktree，preflight capability policy 在 verified phase 隐藏了 git diff/status，只向模型暴露 `finish`，避免一次无效工具调用。
