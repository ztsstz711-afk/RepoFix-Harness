# V3.6 Click upstream help-rendering gate

## Why this case

V3.5 已经证明继续围绕同一个 h11 状态机案例调预算会过拟合，因此 V3.6 扩展到新的项目、目录布局和 Bug 类型。案例来自 Click issue #3298 / PR #3299：option help rendering 会直接执行 `default_value == ""`；若默认对象像 `semver.Version` 一样拒绝与字符串比较，生成帮助文本会抛异常。

这与已有 iterable boundary、parser limit 和 protocol state-machine 案例不同，主要检验 traceback 定位、类型守卫判断、局部补丁和完整框架回归。

## Harness compatibility found during preparation

Click 使用标准 `src/` layout。原 Docker executor 只把仓库挂载到 `/workspace`，没有安装项目，也没有设置仓库内 import path，因此 pytest 在加载 `tests/conftest.py` 时无法导入 `click`。

V3.6 让 Docker 固定使用 `/workspace/src:/workspace`，Local backend 使用解析后的 `<repo>/src:<repo>`。宿主机已有 `PYTHONPATH` 会被覆盖，provider secrets 仍被清除。该机制有单元测试，并通过真实 Docker Click workspace 验证。

由于固定镜像使用 pytest 9.1.1，而该 Click snapshot 把 pytest 10 的一项弃用警告提升为 error，完整验收显式忽略 `pytest.PytestRemovedIn10Warning`；除此之外仍运行全部上游测试。父提交加回归测试的完整 baseline 为 `1 failed, 1385 passed, 21 skipped, 1 xfailed`，fix snapshot 为 `1386 passed, 21 skipped, 1 xfailed`。
