# V1.4 call-aware failure context A/B

## Question

V1.3 的 `username_normalization` 场景是一个明确反例：traceback 指向测试，测试导入 `user_service.build_user_record`，但真正的错误位于它调用的 `formatter.normalize_username`。旧 context 只到达 facade，因此没有缩短后续导航。

V1.4 使用 AST 在已选中的入口函数内寻找实际调用的本地导入函数，只补充一条调用边。它不 import 或执行仓库代码，不展开未调用 import，不递归遍历调用图，并继续服从原有文件数和字符数上限。

## Experiment

- Manifest: `evals/call-context-ab.json`
- Model: `deepseek-v4-flash`
- Backend: restricted Docker, network disabled
- Case: `username_normalization`
- Variants: context-on / context-off
- Repetitions: 3 per variant, interleaved
- Request authorization: 48 maximum
- Expected changed file: `formatter.py`

首轮 context-on trace 在三次 trial 中都记录了相同来源链：

1. `test_user_service.py` — `traceback`
2. `user_service.py::build_user_record` — `local_import`
3. `formatter.py::normalize_username` — `local_call`

## Results

| Metric | context-off | context-on | Relative change |
|---|---:|---:|---:|
| Successful repairs | 3/3 | 3/3 | no change |
| Exact file scope | 3/3 | 3/3 | no change |
| Mean requests | 6.00 | 3.00 | -50.00% |
| Mean tokens | 8,360.00 | 3,946.00 | -52.80% |
| Mean steps | 6.00 | 3.00 | -50.00% |
| Mean estimated cost | $0.00274653 | $0.00175501 | -36.10% |

Overall, the release suite used 27 of 48 authorized requests, 36,918 tokens, and an estimated $0.01350462. All six repairs passed independent final pytest and changed only `formatter.py`. The three context-on trials selected `apply_patch` as their first action; context-off first navigated the repository and read both implementation layers.

Every matched pair favored context-on for requests and tokens. With only three non-tied pairs, the two-sided exact sign-test p-value is 0.25 for both metrics. This is a targeted mechanism check on one deterministic fixture, not statistical evidence of a general 53% improvement.
