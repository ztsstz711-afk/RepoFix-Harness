# V2.1 Provider recovery gate

## Problem

V2.0 的五个失败 trial 中，三个以 invalid model output 结束，两个在格式重试前触发 token reserve。失败 patch step 的输出量接近每次请求的 2,048-token 上限：模型消耗了大量 reasoning，却没有完成 tool call，或把 `apply_patch` 参数截断。

V2.1 增加三项可观测改动：

1. 首次空或非法 native tool response 在原生 schema 下纠错一次，第二次仍失败才降级 JSON。
2. 导航与 patch 阶段拥有独立输出上限；每次 retry admission 使用当前阶段的真实上限。
3. `REPOFIX_THINKING_MODE=auto|enabled|disabled` 显式控制并写入报告；DeepSeek setup 默认选择 `disabled`。

## Bounded gate

`evals/provider-recovery-v2.1.json` 固定 V2.0 中更困难的两个 checksum-qualified 上游案例，各运行一次。每任务最多 12 请求；running min/max 为 40k tokens，Tomli 为 80k tokens。成功必须通过 focused regression、独立完整上游 pytest，并只修改预期实现文件。

| Gate | Verified | Scope | Requests | Input | Output | Total tokens | Format retries | Cost |
|---|---:|---:|---:|---:|---:|---:|---:|---:|
| API default thinking | 0/2 | 1/2 | 17 | 69,708 | 38,430 | 108,138 | 8 | $0.06776712 |
| `thinking=disabled` | 2/2 | 2/2 | 17 | 69,658 | 3,534 | 73,192 | 0 | $0.03117027 |

关闭 thinking 后总 token 减少 32.3%，输出 token 减少 90.8%，估算成本减少 54.0%。running min/max 用 7 requests / 26,733 tokens 完成；Tomli 用 10 requests / 46,459 tokens 完成。两个任务都通过完整 suite，并分别只修改 `more_itertools/recipes.py` 与 `src/tomli/_parser.py`。

## Interpretation and limitation

这是顺序式 before/after 工程门禁，不是同一二进制的随机交错 A/B。两组 source hash 不同，因为第二组加入了显式 thinking 参数和身份记录；核心 Agent Loop、工具策略和任务定义未改变。每个案例每组只有一次，因此结果证明配置值得保留，但不能证明 100% 稳定性。下一步应在冻结的 non-thinking 版本上做重复 trial，再判断改善是否可重复。
