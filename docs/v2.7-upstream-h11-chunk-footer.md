# V2.7 upstream h11 chunk footer calibration

## Goal

V2.7 adds the sixth checksum-qualified real upstream repair and the first protocol state-machine case. The parent h11 implementation discarded two bytes after each chunk body without verifying that they were the required CRLF footer. The upstream regression also exercises footer bytes arriving incrementally, so a valid repair must preserve parser state across calls and reject malformed bytes with `LocalProtocolError`.

Primary provenance:

- Parent commit: https://github.com/python-hyper/h11/commit/31e626c64e1e28db3cd73a6aa0ac057f1b915c18
- Fix commit: https://github.com/python-hyper/h11/commit/dff7cc397a26ed4acdedd92d1bda6c8f18a6ed9f

`scripts/prepare_upstream_h11_chunk_footer_v2.7.ps1` downloads both commit archives, checks hard-coded SHA-256 values, copies the fixed upstream regression test into the parent workspace, and verifies that the Agent-visible implementation remains byte-identical to the parent commit.

The successful trajectory first produced a patch that rejected a valid incremental footer split. It then used the focused failure to revise the state handling: consumed footer fragments are accumulated until both bytes arrive, the complete value is compared with `b"\r\n"`, malformed input raises `LocalProtocolError`, and valid parsing continues. This is semantically equivalent to the upstream fix while using a different internal representation.

At 12/12 requests the model could not issue another finish action. RepoFix's budget-boundary salvage independently ran the configured full suite and accepted the existing patch only after all 78 tests passed. This is a verified repair, not an inferred success from model text.

## Interpretation and limitation

This case is materially harder than the earlier localized iterator guards: correctness depends on preserving a two-byte protocol invariant across incremental reads and revising an initially plausible but incorrect patch. The matrix demonstrates that RepoFix can complete the repair under a larger bounded budget, while also exposing strong trajectory and budget sensitivity.

The four runs are not repeated trials of a frozen policy and must not be combined into a 1/4 success-rate estimate. The 72k result is a final budget calibration, not evidence of stable success on this bug family or arbitrary protocol parsers. A future stability claim requires independent repetitions of one frozen configuration.
