# V1.5 upstream bug suite

## Goal

V1.5 从人工注入回归转向真实上游修复。一个案例只有同时满足以下条件才进入 suite：

1. 固定公开上游 repository、父 commit 和修复 commit。
2. 修复 commit 同时包含实现修改和可独立运行的回归测试。
3. buggy workspace 保留父 commit 的实现，只复制修复 commit 中的测试文件。
4. buggy 完整测试稳定失败，fixed reference 完整测试稳定通过。
5. 不需要网络、数据库或外部服务即可在受限 Docker 中验证。

这不是 SWE-bench。它是一个更小、可人工审计的真实 commit-level repair suite，用于先验证 RepoFix 对未知第三方代码和真实上游语义的适应能力。

`scripts/prepare_upstream_bugs.ps1` downloads parent and fix archives from GitHub codeload, verifies six hard-coded SHA-256 values, keeps complete fixed references, and emits a provenance file outside each Agent-visible buggy repository. The script copies only changed upstream test files into the parent source and verifies that every protected implementation file remains byte-identical to the parent archive.

## Offline qualification

Qualification used the same `repofix-pytest:latest` image as evaluation, with networking disabled, a read-only source mount, no capabilities, no privilege escalation, 512 MB memory, one CPU, and 256 PIDs.

| Case | Buggy full suite | Fixed full suite |
|---|---:|---:|
| Negative `sliced()` size | 1 failed, 729 passed | 730 passed |
| Stable running min/max | 2 failed, 730 passed | 732 passed |
| Dotted key part limit | 1 failed, 16 passed | 17 passed |

The more-itertools runs additionally completed 19,938 subtests. The Tomli run completed 744 subtests. These counts establish a deterministic before/after oracle before any model request is authorized.

## Evaluation contract

- Docker execution only; no repository test code runs directly on the host.
- Full upstream test command is reused for independent baseline and final verification.
- One trial per case for the first gate.
- Maximum 12 requests per task; token limits are 32,000 for the smaller boundary case and 40,000 for the two cases requiring broader navigation or multiple edits.
- Suite authorization: 36 requests total.
- Expected changed files are evaluation metadata and are never included in the model prompt.

The first gate is a feasibility measurement, not a success-rate benchmark. Repetitions and broader repositories should be added only after all three cases have deterministic environment behavior and at least one bounded end-to-end run.

An initial 24,000-token calibration gate completed the boundary case but stopped the other two at the pre-request reserve check. One had correctly changed the expected file but still needed a second symmetric edit and verification; the other had located the parser function but had not patched it. The revised limits preserve the 12-request and 36-request suite authorization while allowing realistic third-party repository navigation. The incomplete calibration output is retained locally and is not reported as a successful benchmark.
