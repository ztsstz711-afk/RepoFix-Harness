# V0.8 Run management

V0.8 turns run artifacts into an operational recovery interface rather than passive JSON files.

## Commands

```text
repofix-runs --repo <repo> list
repofix-runs --repo <repo> show <run-id|latest>
repofix-runs --repo <repo> rollback <run-id|latest> [--force]
```

`list` returns compact run summaries. `show` reads either `result.json` or the latest checkpoint trace. `--json` produces machine-readable output for list and show operations.

## Conflict-safe rollback

After each successful Agent write, `WorkspaceJournal` stores the resulting SHA-256 hash. Manual rollback compares the current file to that hash before restoring anything. A mismatch means the file was edited after the run, so rollback fails without changing any tracked file.

`--force` bypasses end-hash conflicts but cannot bypass missing backups, unsafe paths, or non-file restore targets. All tracked files are preflighted before restoration begins.

## Run identity and latest pointers

Run IDs accept only letters, numbers, underscores, and hyphens. This prevents artifact path traversal. Restoring an older run updates that run's own result while leaving `.repofix/result.json` and `.repofix/trace.json` pointed at the actual latest run.

A journal can be rolled back once. A resumed Agent write clears the rollback marker and creates a new pending workspace state while retaining the original task-start snapshot.
