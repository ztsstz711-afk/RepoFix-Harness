# V4.9 held-out upstream results

## Result

RepoFix passed the first-use held-out gate frozen in commit `5365cd6`: **2/3 independently verified repairs**, exact changed-file scope on all three attempts, and a schema-v3 report accepted by the internal aggregate validator.

| Metric | Result |
|---|---:|
| Verified repairs | 2/3 (66.7%) |
| Exact scope among successes | 2/2 (100%) |
| Exact scope across all attempts | 3/3 (100%) |
| Model requests | 27/36 authorized |
| Total tokens | 82,275 |
| Retries | 0 |
| Estimated API cost | $0.02958065 |
| Wall-clock evaluation time | about 89 seconds |

The three upstream bugs and their budgets were committed before the Agent was run. Each bug was new to RepoFix development and received one formal attempt; no failed task was replaced, rerun, or granted extra budget.

## Trial outcomes

| Project | Outcome | Requests | Tokens | Changed file | Acceptance |

All focused baselines failed before repair. The corresponding upstream-fix snapshots had already passed the same focused checks and larger acceptance commands, so the test oracles were not vacuous.

## What the failure shows

The Packaging Agent edited only the correct implementation file but entered two patch-revision cycles. With 30,448 of 32,000 authorized tokens consumed, the admission controller refused a further estimated 4,131-token request. This is a genuine bounded failure: locating and scope selection were correct, but the trajectory did not converge before the frozen budget.

The result supports two separate claims:

- RepoFix can generalize beyond its development fixtures: two unseen upstream bugs were repaired and independently verified on the first formal attempt.
- Long revision trajectories remain a limitation even for a localized bug, consistent with the budget-bound failures observed in V4.8.
