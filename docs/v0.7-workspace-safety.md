# V0.7 Workspace safety

V0.7 makes repository recovery a Harness responsibility while keeping rollback opt-in.

## Run-level journal

`WorkspaceJournal` stores the original bytes of a path before the first real write in a run. Later writes to the same path reuse that snapshot, so rollback returns to the task's starting state rather than the previous Agent step. New files are recorded without a backup payload.

Artifacts live under `.repofix/runs/<run_id>/workspace/`:

- `manifest.json` maps repository-relative paths to existence and SHA-256 metadata.
- `backups/<hash>.bin` stores original bytes without exposing source filenames in backup paths.

The normal tool permission policy hides `.repofix` from the Agent.

## Changed-file limit

The default limit is five distinct files. Rewriting an already tracked file is allowed, and a byte-identical write does not consume the limit. Set `--max-changed-files 0` for no limit.

## Failure rollback

`--rollback-on-failure` restores tracked existing files atomically and removes tracked files that the Agent created. Successful runs are never rolled back. The result preserves the pre-rollback final test result and adds:

- `rollback_performed`
- `rollback_files`
- `post_rollback`
- `rollback_error`

If recovery itself fails, the original run status is preserved and the recovery error is checkpointed instead of crashing the CLI. Provider errors, exhausted budgets, verification failures, and stalled loops can all trigger rollback when enabled.
