# V2.8 context compaction and failure-line relevance

## Motivation

The V2.7 h11 trajectory reached 23,290 context characters and consumed 66,476 model tokens before succeeding at the request boundary. Inspection of the persisted context snapshots exposed three reusable Harness problems:

1. the 4,116-character initial baseline failure was repeated after a newer focused pytest failure superseded it;
2. repeated reads of the same file range retained both obsolete and current source copies;
3. traceback import expansion followed module import order, so the h11 failure line mentioning `ChunkedReader` could receive unrelated imports first.

V2.8 changes only context construction. It does not alter tool permissions, acceptance tests, source files, or evaluation oracles.

## Changes

### Superseded baseline output

The full independent baseline remains available until the history contains a `run_command` result or automatic post-patch pytest result. After that point, ContextBuilder retains the baseline status and command but removes its old output because the newer test observation is already present in the recent trace.

Each context snapshot records `baseline_output_superseded`, so this decision is auditable. The baseline `TestSnapshot` in the run result remains unchanged.

### Latest navigation evidence

For model context only, repeated reads with the same path and line range and repeated searches with the same query and path keep the latest event. This matters after a patch because the latest read reflects current source while an older read may describe code that no longer exists.

The persisted run history is not mutated. Snapshot metadata records `history_events_deduplicated` alongside total, included, omitted, and oversized-event counts.

### Failure-line import relevance

When a traceback points into a test file, local import expansion now first identifies names used on the exact failing source line. If one or more imported bindings occur there, unrelated imports are excluded from the bounded source selection. Existing facade and one-hop local-call expansion continue to operate on the selected symbol.

## Deterministic validation

No provider requests were used for V2.8 validation. The successful V2.7 h11 history was replayed through the new ContextBuilder using the same task, baseline, and event prefixes.

| Request step | V2.7 context chars | V2.8 replay chars | Reduction |
|---:|---:|---:|---:|
| 8 | 20,729 | 16,663 | 4,066 |
| 9 | 23,140 | 19,074 | 4,066 |
| 10 | 21,000 | 20,489 | 511 |
| 11 | 23,290 | 20,402 | 2,888 |
| **Steps 8–11 total** | **88,159** | **76,628** | **11,531** |

The exact numbers are an offline replay diagnostic, not a token-cost forecast: provider-side system prompts, tool schemas, caching, and tokenization are not represented by character counts.

Using the frozen V2.7 h11 baseline against the prepared source workspace, failure source selection became:

| Source | Reason | Symbol |
|---|---|---|
| `h11/tests/test_io.py:469` | traceback | failing statement |
| `h11/_readers.py:148` | local import | `ChunkedReader` |
| `h11/_util.py:59` | local import | `LocalProtocolError` |

The new selection is 2,833 characters and directly covers the parser implementation and expected exception. It no longer spends the four-file cap on unrelated earlier imports such as event or header types.

## Scope and limitation

The deterministic mechanism validation demonstrates smaller, more relevant prompts for this history. Two subsequently frozen real-model gates tested whether that translated into reliable repair under bounded budgets.

## Frozen real-model gates

Both suites used `deepseek-v4-flash`, explicitly disabled thinking, the same checksum-qualified V2.7 h11 source snapshot, independent Docker-isolated copies, a focused regression during iteration, and `pytest -q h11` for final acceptance. The expected scope was only `h11/_readers.py`.

## Interpretation

V2.8 improves deterministic context relevance and removes known duplication, but the frozen gates show that this alone does not make the complex incremental parser repair stable. A larger token budget raised the observed result from 0/3 to 1/3, while two 72k trajectories still exhausted different budget dimensions. The correct conclusion is a measured capability boundary, not a generalized success claim.
