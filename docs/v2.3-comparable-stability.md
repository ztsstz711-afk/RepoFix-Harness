# V2.3 comparable stability gate

## Comparison contract

`evals/comparable-stability-v2.3.json` 复用 V2.0 的三个 checksum-qualified 上游 Bug、相同任务文本、focused regression、完整 pytest 和 expected changed-file acceptance。每案例运行三次并按轮次交错，共 9 trials。

V2.3 使用 `deepseek-v4-flash`、`thinking=disabled`、native tool retry、patch-phase output ceiling 和 revision cap。为了容纳已观测到的二次修订，running 与 Tomli 的 token ceiling 从 V2.0 的 40k/68k 调整为 45k/80k；每任务 request ceiling 仍为 12。该预算差异必须与结果一起说明。

所有 success 都通过独立完整上游 pytest，并且只修改预期实现文件。唯一失败的 Tomli trial 没有写入文件：模型连续猜测不存在的 `_parse_key`，两个 exact patch 被安全拒绝，最终用尽 12-request budget。

## Follow-ups kept separate

1. No-op patch rejection 在 registry 层拒绝 `old_text == new_text`。独立 Tomli gate 为 0/1；模型后来写入了不完整补丁，但没有在 12 请求内完成修订。这证明输入卫生改进正确，却不能单独声称提高成功率。
2. Search evidence 改进让零匹配明确返回 `No matches found`，不再计入 patch readiness；三次空搜索且尚未读取源码时进入 `search_exhausted`，只暴露 `list/read`。独立 Tomli gate 为 1/1，完整 suite 与改动范围均通过，使用 12 requests / 60,134 tokens。

主门禁仍报告 8/9；两个 follow-up 不与主结果合并或用于挑选成功样本。
